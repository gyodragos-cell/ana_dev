# Public Naming Policy

Purpose: keep public wording professional, clear, and privacy-safe.

## Public Name

Use this for demos, school pages, release pages, and user-facing text:

```text
JokerForge
```

Use this as a descriptive subtitle when useful:

```text
local-first AI tooling for observation, voice feedback, diagnostics, and assistive workflows
```

## Internal Codename

`ANA` is allowed only as an internal codename in code, old file paths, tests,
and private development notes. Do not present it as the public product name.

## Tool Names

Use descriptive tool names in public:

- MCP Voice Cockpit
- Chat Voice Bridge
- Desktop Vision Diagnostic
- Frida Runtime Tool
- Quality Gate
- Desktop Vision Assist

Avoid public labels like:

- ANA Frida
- ANA voice
- ANA user watcher
- ANA hacking demo

## Privacy Boundaries

Public copy must say or imply:

- local-first
- educational or assistive use
- no private logs published
- no API keys or personal data exposed
- no inspection without permission

## Release Rule

Before publishing anything, scan for:

```text
ANA MAX
A.N.A.
api key
token
C:\Users\
file:///
```

If the text is public-facing, replace internal names with descriptive wording.
